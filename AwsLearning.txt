you can put your server, databases and 	other resouces inside this network

Think of it as your own data center in the cloud.

 2. AWS VPC Practical Demo (What happens in practice?)
 ******************************************************

Step 1: Create a VPC → Choose CIDR block (e.g., 10.10.0.0/16)
Step 2: Create Subnets → Divide VPC into smaller parts (e.g., 10.10.1.0/24)

Public Subnet → Can access the internet
Private Subnet → No direct internet access


Step 3: Add Internet Gateway → Allows public subnet to talk to the internet
Step 4: Configure Route Tables → Decide which subnet can go where
Step 5: Launch EC2 instances inside subnets

3. AWS VPC Subnets & CIDR Block
*************************
CIDR block defines the IP range.

Example: 10.10.0.0/16 means 65,536 IP addresses.


Subnet is a smaller range inside VPC.

Example: 10.10.1.0/24 means 256 IP addresses.

 4. VPC Peering
*******************
What is it?

Connect two VPCs so they can talk to each other.


Why use it?

If you have multiple VPCs (maybe in different regions or accounts) and need them to share data.


Important: VPC Peering does NOT allow transitive routing (A → B → C is not possible).

What is AWS EFS?
****************
Amazon Elastic File System (EFS) is a scalable, cloud-native Network File System (NFS) that allows multiple EC2 instances
 to access the same file system concurrently. It’s designed for Linux-based workloads and supports NFSv4.1 and NFSv4.2 protocols.

🔹 Key Features

Fully Managed: No need to provision or manage storage.
Elastic: Automatically scales up or down as files are added or removed.
Shared Access: Multiple EC2 instances can mount the same file system.
Durability & Availability: Data is stored redundantly across multiple Availability Zones.
Performance Modes:

General Purpose: Balanced for latency and throughput.
Max I/O: Optimized for higher throughput workloads.

🔹 Use Cases

Web serving and content management
Big data and analytics
Media processing workflows
Container storage (e.g., with Amazon ECS or EKS)
Home directories for users


🔹 Pricing
You pay for:

Storage used (GB/month)
Provisioned throughput (if using Provisioned Throughput mode)
Data transfer (cross-region or to/from on-premises)


🔹 How to Use EFS

Create a File System in the AWS Console.
Configure Mount Targets in each Availability Zone.
Mount the File System on EC2 instances using the NFS client.
Access Files just like a local file system.

Amazon S3 (Simple Storage Service) 
********************************
it is object storage service that provides
Unlimited Secure Object Storage for any amount of data.
Buckets: Containers for storing objects. Each bucket name must be globally unique across AWS.
Regions: Buckets are created within a specific AWS region.
Folder Structure: Logical organization using prefixes (Folder → Subfolder → Files).
File Size: Supports objects from 0 KB up to 5 TB.
Security:

Encryption in transit (data moving between client and S3).
Encryption at rest (data stored in S3).


Availability: 99.99% uptime (approx. 13 minutes downtime per year).
Durability: AWS replicates data across multiple devices and Availability Zones (AZs).

S3 Storage Classes
*********************
Standard: For frequent access.
Infrequent Access (IA): Lower cost for data accessed less often.
Archive (Glacier): For long-term storage at minimal cost.

S3 Versioning
***************
Allows you to keep multiple versions of an object in the same bucket.
Protects against accidental deletion or overwriting.
Can be enabled at the bucket level.
Useful for backup and recovery scenarios.
